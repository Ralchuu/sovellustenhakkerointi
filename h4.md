# b) rever-C.

Tein Ghidrassa uuden projektin valitsemalla File - New Project. Valitsin vaihtoehdoksi Non-Shared Project.

Importtasin packd-tiedoston valitsemalla File - Import File -> Packd

Näytölle tuli import resultsina jotain perustietoa filestä.

<img src="https://raw.githubusercontent.com/Ralchuu/sovellustenhakkerointi/main/h4tehtava04.png" width="800">

Avasin packd, ja ensiksi Ghidra kysyy että haluanko analysoida tiedoston. 

<img src="https://raw.githubusercontent.com/Ralchuu/sovellustenhakkerointi/main/h4tehtava02.png" width="800">

Tein samanlailla kuin X-tehtävän videolla eli valitsin kyllä ja käytin Ghidran valmiiksi asettamia vaihtoehtoja.

<img src="https://raw.githubusercontent.com/Ralchuu/sovellustenhakkerointi/main/h4tehtava03.png" width="800">

Huomasin että decompile-kohdassa ei näy mitään main-function kohdalla, tajusin hetken päästä että tämä on UPX-paketoitu versio niin todennäköisesti siksi Ghidra ei pysty lukemaan sitä. Vaihdoin purettuun packd-tiedostooni "packd-unpacked".

Navigoin main-functioon Symbol tree -> Functions -> Main ja lähdin muuttamaan muuttujien nimiä.

<img src="https://raw.githubusercontent.com/Ralchuu/sovellustenhakkerointi/main/packdunpacked.png" width="800">

Koska "iVarl" on muuttuja strcmp-funktiolle joka vertaa että täsmääkö salasana inputtiin niin nimesin sen "doesPasswordMatch"

"local_28" on syöte joka tulee sanasalan kohtaan joten nimesin sen "password"

Rivillä 9 on käytetty scanf-funktiota, siistin sen nimeä _isoc99_scanf -> scanf

&DAT_0010201d kanssa jouduin ihmettelemään pitkään että mitä tähän tulisi laittaa, tuplaklikkasin sitä ja koitin lukea siitä listings-osiosta vasemmalla. Selvitin että DAT on Ghidran automaattisesti antama nimi datalla ja 0010201d on muistiosoite datalle.

Kyseisen muistiosoitteen kohdalla näkyy "%19s" joka tarkoittaa C-kielessä että kyseessä on string ja sille on varattu 19 merkkiä tilaa muistista. Laitoin siis &DAT_0010201d tilalle "%19s" jotta koodi on ihmiselle ymmärrettävää.

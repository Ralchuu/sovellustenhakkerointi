# Analyse the image file

Aloin tutkia `binwalk`-havainnoista löytyneitä tietoja.

## Havainnot

Firmware sisältää MIPS Linux -ytimen. `binwalk` löysi muun muassa seuraavat tiedot:

```text
uImage header
OS: Linux
CPU: MIPS
image name: mips Ingenic Linux-3.10.14
```

Tämä kertoo, että kamera käyttää Ingenic/MIPS-alustaa ja Linux-kernelin versio on `3.10.14`.

Kernel on LZMA-pakattu:

```text
LZMA compressed data
```

Firmware sisältää myös SquashFS-root-tiedostojärjestelmän:

```text
squashfs filesystem, little endian, version 4.0
compression: xz
size: 3032084 bytes
96 inodes
```

Firmwaresta löytyy siis Linux-rootfs.

Rootfs käyttää XZ-kompressiota.

Firmwarella on aikaleima `13.3.2025`.

Kokeilin tutkia purettua rootfs:ää tarkemmin seuraavilla komennoilla:

```bash
ls -la _Tapo_C200v4_en_1.4.2.bin.dec-0.extracted/squashfs-root

find _Tapo_C200v4_en_1.4.2.bin.dec-0.extracted/squashfs-root -maxdepth 2 -type f | sort

find _Tapo_C200v4_en_1.4.2.bin.dec-0.extracted/squashfs-root -type f -perm /111 -print
```

![Rootfs tiedostoja](https://raw.githubusercontent.com/Ralchuu/sovellustenhakkerointi/main/h6p7.png)

![Rootfs executable-tiedostoja](https://raw.githubusercontent.com/Ralchuu/sovellustenhakkerointi/main/h6p8.png)

Sieltä löytyi monta kiinnostavaa executable-ohjelmaa, kuten:

```text
/bin/main
/bin/gdbserver
/bin/impdbg
/usr/bin/iperf
/usr/sbin/hostpd
```

# Extract rootfs from the dump file

Ajoin ensin `binwalk`-komennon kameran dump-tiedostolle:

```bash
binwalk dump-tapo-c200v3-1.4.2.bin
```

![Binwalk dump-tiedostosta](https://raw.githubusercontent.com/Ralchuu/sovellustenhakkerointi/main/h6p9.png)

Tein kansion dumpin rootfs:lle:

```bash
mkdir -p dump-rootfs
```

Tämän jälkeen suoritin seuraavat komennot:

```bash
dd if=dump-tapo-c200v3-1.4.2.bin of=dump-rootfs/rootfs.squashfs bs=1 skip=4456448

unsquashfs -d dump-rootfs/squashfs-root dump-rootfs/rootfs.squashfs
```

# Tapo C200 -kameran ohjelmiston turvallisuus

Katselin ensin kaikkia tiedostoja kokojärjestyksessä komennolla:

```bash
du -ah . | sort -h | tail -50
```

![Tiedostojen koot](https://raw.githubusercontent.com/Ralchuu/sovellustenhakkerointi/main/tapo1.png)

Tämän jälkeen kokeilin etsiä ohjelmasta turvallisuuteen, autentikointiin ja verkkopalveluihin liittyviä merkkijonoja:

```bash
strings -a bin/main | grep -Ei 'password|passwd|secret|token|admin|debug|telnet|ssh|http|https'
```

Löytyi kokonainen RTSP-palvelimen toteutus.

RTSP ei näytä olevan vain avoin streami, vaan siinä on jonkinlainen käyttäjän ja autentikoinnin tarkistus.

![RTSP-palvelimeen liittyviä stringejä](https://raw.githubusercontent.com/Ralchuu/sovellustenhakkerointi/main/tapo3.png)

Pelkällä `strings`-komennolla en löytänyt suoria haavoittuvuuksia, joten päätin tutkia asiaa tarkemmin Ghidrassa.

![RTSP-koodin tutkiminen Ghidrassa](https://raw.githubusercontent.com/Ralchuu/sovellustenhakkerointi/main/tapo5.png)

Koodissa esiintyy IP-osoitteeseen perustuva lukitusmekanismi sekä `factory_mode`-asetukseen liittyvä poikkeava autentikointitila.

Näiden toimintojen turvallisuus vaatii lisäanalyysiä.

![IP-osoitteeseen ja factory\_modeen liittyvä koodi](https://raw.githubusercontent.com/Ralchuu/sovellustenhakkerointi/main/tapo6.png)

Tutkin jonkin aikaa lisää, mutta en löytänyt muita selkeitä haavoittuvuuksia. Päätin katsella muualta.

Löysin kuitenkin autentikoinnin kannalta mahdollisen suoran bypass-ehdon: jos tämän `state`-arvo on nolla, funktio hyväksyy pyynnön menemättä Digest-tarkistukseen.

![Mahdollinen autentikoinnin bypass](https://raw.githubusercontent.com/Ralchuu/sovellustenhakkerointi/main/tapo8.png)
